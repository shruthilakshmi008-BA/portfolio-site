About

I started in engineering. I stayed for the problem-solving.

My work begins with a business problem, not a system. I run discovery with stakeholders, map how a process actually works today, find where it breaks, and translate that into requirements a technical team can build against without guessing.

Because I came up through software engineering and automation consulting, I can go a layer deeper than the requirement itself — reviewing API and access design, writing the SQL to check whether the data supports the assumption, and sitting in technical clarification sessions before a line of code is written. That's the part of the work I want to keep doing: not choosing between business and technology, but being the person who connects them.

Capstone · Personal Project

Enterprise Order-to-Cash (O2C) Pipeline

Problem: Order and invoice data arrives with inconsistent status labels and unstructured invoice text, while a hard financial control — anything at or above $5,000 needs human sign-off — has to hold regardless.

Solution: A working pipeline that normalises statuses (dictionary rules first, live Gemini API for unmapped values), extracts invoice fields via regex, enforces the compliance threshold, and auto-drafts BDD user stories for every flagged exception. It ships with a full SDLC documentation set — BRD, FRD, Requirements Traceability Matrix, UAT plan and generated backlog — written only after real tests were executed against the real code.

Why it matters: The design principle throughout is fail safe, never guess: an unreadable invoice total is treated as unknown and routed to review, never defaulted to $0.00, because a silent zero could slip a high-value order past the compliance check.

Status Cleaner

Solution: A two-tier normaliser: deterministic dictionary matching first, LLM classification only for values the rules don't recognise. Every row carries a method_used column so the routing is auditable.
